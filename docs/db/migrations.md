# Міграції (Alembic)

## Політика міграцій
- Zero-downtime, якщо можливо: спершу **add-only**, потім backfill, потім switch.
- Кожна міграція — **ідемпотентні** SQL у `upgrade()`/`downgrade()`.
- Обов’язково: тест міграції на локальній БД.

## Приклад життєвого циклу
1) Додаємо колонку (nullable) → деплой
2) Заповнюємо дані (скрипт/джоб) → перевірка
3) Робимо not null/індекс → деплой
4) Видаляємо застарілі поля — окремою міграцією, коли впевнені

## Налаштування Alembic
- Тримати `alembic.ini` і `alembic/` (версії) в репозиторії
- Окреме підключення для local/stage/prod
- Лог змін — з коментарями «чому», посилання на ADR/Issue
